## What this is

Scroll-triggered reveals make a page feel alive, but they can also hide content
from people who use screen readers, trigger nausea for readers with vestibular
disorders, and leak animations between page navigations in React. This site
documents one way to get the effect without those costs.

Everything lives in one file, `lib/motion.ts`, with three helpers:

- `motionAllowed()` checks the operating system setting and an on-site toggle
  before anything moves.
- `fadeUp()` fades elements up once as they scroll into view. It animates
  opacity only, so the content stays in the accessibility tree the whole time.
- `settleAnimations()` finishes every running animation the moment a reader
  turns motion off.

Components call these helpers from the `useGSAP()` hook, which scopes selectors
to one component and reverts every animation when the component unmounts.

## Who it's for

- React developers who know the basics of the Next.js App Router and are new to
  GSAP.
- Teams that want scroll animation on a marketing, product, or nonprofit site
  and need to meet accessibility expectations such as WCAG 2.2 success
  criterion 2.3.3, Animation from Interactions.

This site doesn't cover page transitions, smooth-scrolling libraries, or canvas
and WebGL animation.

Every code sample on this site was run in a fresh `create-next-app` project
with these versions:

| Package | Version |
| --- | --- |
| `next` | 16.4.2 |
| `react` | 19.3.0 |
| `gsap` | 3.15.0 |
| `@gsap/react` | 2.1.2 |
| Node.js | 24.12.0 |

The same helpers also run in production on Next.js 14.2 with React 18.
