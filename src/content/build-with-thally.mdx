I built this site to document a pattern I keep reusing on client projects:
scroll animation with GSAP in the Next.js App Router that doesn't get in the way
of people who need less motion. This is how I put it together and published it
with Thally Cloud, so you can do the same with a topic of your own.

The site is small on purpose: an [introduction](/), a [quickstart](/quickstart),
one [practical guide](/guides/reduce-motion-toggle), and a short reference. The
source is on GitHub at
[Delali34/accessible-scroll-motion](https://github.com/Delali34/accessible-scroll-motion)
if you want to follow along.

Setting up Thally took a few minutes. Most of my time went into writing the
pages and testing the code in them. I wrote this in October 2026 with
`@thallylabs/cli` 0.8.124 and `create-thally-docs` 0.10.121, so some details
may have changed since.

## What you need

- A Thally Cloud account. New workspaces get a 7-day trial with room for three
  sites.
- A GitHub account where you can install the Thally GitHub App.
- Node.js 20.19+, 22.14+, or 24+ and Git, if you want to edit and check content
  on your machine. You don't need either just to publish the starter site.
- A topic you know well. Keep it narrow. A small site with code that works is
  better than a big one with samples nobody has run.

## 1. Create the site in Thally Cloud

Sign up at [app.thally.io](https://app.thally.io). You can use GitHub, Google,
or email. Google didn't work for me (it ended with "Error 401:
deleted_client"), so I used email. After you verify your email and answer a few
onboarding questions, select **Create a site** on the Home page. The wizard has
five steps:

1. **Site details.** A name, a one-line summary of up to 240 characters, and a
   `thally.app` address. The address doesn't fill in from the name, so type it
   yourself. Thally tells you straight away whether it's available.
2. **Docs source.** Choose **Create a new docs repository**, select **Check
   GitHub**, and approve the Thally GitHub App. It needs **All repositories**
   access so it can create the new repository for you. This is also where you
   choose whether the repository is private. I made mine public so anyone can
   read the source.
3. **Product sources.** Pick the repositories Thally Track should watch, or
   select **Skip for now**. Track works from merged pull requests, so it won't
   notice commits pushed straight to the main branch.
4. **Knowledge surfaces.** Optional. Skip it unless you have another repository,
   like a marketing site, that should get update PRs too.
5. **Review and publish.** Check the summary and select **Publish site**.

Thally creates the repository from its starter template and deploys it. Mine
was live in about a minute.

## 2. Get to know the repository

Clone the repository from the link on the site summary and install the
dependencies:

```bash
git clone https://github.com/YOUR_ACCOUNT/YOUR_REPO.git
cd YOUR_REPO
npm ci
```

There are around 400 files, but you'll only work in a few of them:

| Path | What it's for |
| --- | --- |
| `src/content/**/*.mdx` | Your pages. Each one needs `title` and `description` frontmatter. |
| `docs.json` | Tabs, sidebar groups, and page order |
| `src/data/site.ts` | Site name, description, and header links (Thally fills these in for you) |
| `AGENTS.md` | Instructions for coding agents, with a "Product context" section for you to fill in |
| `README.md` | Yours to rewrite |

The rest is the Thally runtime. `starter-release.json` spells out which files
are yours; `README.md` and `AGENTS.md` are both marked
`userOwnedNeverOverwrite`. It's worth reading `AGENTS.md` before you start,
because it covers the writing style and which files to leave alone.

## 3. Replace the starter content

The starter comes with example pages about Thally itself. Delete the ones you
don't need with `git rm`, then update `docs.json` so it only lists pages that
exist. Here's the navigation for this site, including the tab you're reading:

```json title="docs.json"
"tabs": [
  {
    "tab": "Docs",
    "groups": [
      { "group": "Get started", "pages": ["introduction", "quickstart"] },
      { "group": "Guides", "pages": ["guides/reduce-motion-toggle"] },
      { "group": "Reference", "pages": ["reference/motion-helpers"] }
    ]
  },
  {
    "tab": "Build with Thally",
    "groups": [{ "group": "Article", "pages": ["build-with-thally"] }]
  },
  { "tab": "Changelog", "href": "/changelog" }
]
```

My topic doesn't have an HTTP API, so I removed the **API Reference** tab and
`openapi.yaml`. Without a spec, `/openapi.yaml` describes the site's own
read-only API instead, so nothing breaks.

These are the components I used. They all come with the starter:

- `<Hero>` on the introduction page, which has `mode: home` in its frontmatter
- `<Steps>` and `<Step title="…">` for the quickstart and the guide
- `<CardGroup cols="3">` and `<Card icon="…" href="…">` for links to other
  pages. Icon names come from an allowlist in
  `src/components/mdx/content-icon.tsx`.
- `<Note type="info|tip|warning|danger">` for callouts
- Code blocks with a filename: `` ```tsx title="lib/motion.ts" ``

For troubleshooting, use `###` headings. Each one gets a stable anchor, like
[this one](/guides/reduce-motion-toggle#cards-stay-invisible-after-turning-on-reduce-motion),
so other pages can link straight to it.

## 4. Test your code samples

If you only take one thing from this article, take this one. I created a fresh
app with the same command as my quickstart,
`npx create-next-app@latest motion-demo --yes`, pasted in every sample, and ran
it in a browser. It caught three things I would have published otherwise:

- My first version of the toggle set React state inside `useEffect`. The
  current `eslint-config-next` rejects that (`react-hooks/set-state-in-effect`),
  so I rewrote it with `useSyncExternalStore`.
- The inline `<script>` in `layout.tsx` logs "Encountered a script tag while
  rendering React component" after Fast Refresh, but not on a full page load.
  That's now a troubleshooting entry.
- Using `useEffect` with `gsap.from()` under Strict Mode left an element stuck
  at `opacity: 0.0232`. That one's in the
  [troubleshooting section](/guides/reduce-motion-toggle#troubleshooting) too.

It also helps to list the versions you tested with, so readers know what
"works" means.

## 5. Check and build

Run Thally's check and a production build before every push:

```bash
npx --yes @thallylabs/cli@latest check
npm run build
```

On Windows, `check` failed for me with:

```text
'C:\Program' is not recognized as an internal or external command,
operable program or batch file.
```

The CLI starts Node through the shell, and the space in `C:\Program Files`
breaks the path. Running the check from its underlying package works fine:

```bash
npx --yes create-thally-docs@latest check . --ci
```

The bug is tracked in
[thallylabs/thally#333](https://github.com/thallylabs/thally/issues/333), and
I've opened a fix in
[thallylabs/thally#342](https://github.com/thallylabs/thally/pull/342).

The build took about a minute and a half on my machine. After that, I ran
`npm run dev`, opened `http://localhost:3040`, and clicked through every page to
make sure the code blocks and links looked right.

## 6. Publish

Commit your changes and push them to `main`:

```bash
git add docs.json src/content AGENTS.md README.md
git commit -m "Add docs"
git push origin main
```

Thally picks up the push and shows it under **Recent activity**, first as
**Building** and then as **Successful**. Mine took about two minutes. Then check
it from outside the dashboard:

```bash
curl -I https://YOUR-SITE.thally.app/quickstart
curl https://YOUR-SITE.thally.app/llms.txt
```

You also get a Markdown version of every page (add `.md` to the URL),
`llms.txt`, `AGENTS.md`, `skill.md`, and a read-only MCP endpoint at
`/api/mcp`, all from the same MDX files. Once my content was live, the agent
readiness score went from 89 to 97.

## What tripped me up

| Problem | What I did |
| --- | --- |
| **Continue with Google** failed with "Error 401: deleted_client" | Signed up with email instead |
| `thally check` failed on Windows with `'C:\Program' is not recognized…` | Used `npx --yes create-thally-docs@latest check . --ci`, then opened a fix ([#342](https://github.com/thallylabs/thally/pull/342)) |
| My first toggle failed the project's lint rules | Rewrote it with `useSyncExternalStore` after testing it in a fresh app |

## What's next

- Add a custom domain from the site's domain settings. Thally shows you the DNS
  records to add at your DNS provider.
- Fill in the "Product context" section of `AGENTS.md` so Thally Track and
  coding agents use your terminology.
- Connect your editor to the local authoring MCP server
  (`npx -y @thallylabs/mcp`) and to your site's read-only MCP endpoint
  (`https://YOUR-SITE.thally.app/api/mcp`).
