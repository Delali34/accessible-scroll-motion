This walkthrough shows how I built and published this site, a small
documentation site for adding GSAP scroll animation to a Next.js App Router
project. Follow it to publish your own: one [introduction](/), one
[quickstart](/quickstart) that works, and one [practical guide](/guides/reduce-motion-toggle),
all deployed from a GitHub repository. The source for this site is
[Delali34/accessible-scroll-motion](https://github.com/Delali34/accessible-scroll-motion)
if you want to compare.

It covers the managed Thally Cloud path. The Thally setup itself took
minutes. Most of the time went into writing the docs and testing the code in
them.

Written in October 2026 against `@thallylabs/cli` 0.8.124 and
`create-thally-docs` 0.10.121.

## Prerequisites

- A Thally Cloud account. A new workspace gets a one-time 7-day trial on first
  sign-in, with room for three sites.
- A GitHub account that can install the Thally GitHub App.
- Node.js 20.19+, 22.14+, or 24+, plus Git, for editing and checking content
  locally. You don't need either to publish the starter site.
- Something you know well enough to document. Pick a narrow topic. A small site
  with code that works beats a broad site with untested samples.

## 1. Create the site in Thally Cloud

Sign in at [app.thally.io](https://app.thally.io). You can use GitHub, Google,
or email. When I wrote this, **Continue with Google** failed with "Error 401:
deleted_client", so I signed up with email instead. A new account verifies its
email address and then goes through a short onboarding questionnaire. Then
select **Create a site** on the workspace Home page. The wizard has five steps.

1. **Site details.** Enter a site name, a one-line summary of up to 240
   characters, and a `thally.app` address. The address field doesn't fill
   itself from the name, so type it. Thally checks availability as you type and
   confirms with "*address* is available".
2. **Docs source.** Choose **Create a new docs repository**, then select
   **Check GitHub** and approve the Thally GitHub App. Creating a fresh
   repository needs **All repositories** access, because the app has to
   initialize a repository that doesn't exist yet.

   The new repository defaults to **Private**. If anyone outside your GitHub
   account needs to read the source, such as reviewers or contributors, turn
   **Private repository** off here.
3. **Product sources.** Pick the repositories that Thally Track should watch, or
   select **Skip for now**. Track reads *merged pull requests*, so a repository
   where you push straight to the default branch won't produce any updates
   until you start merging PRs. Your docs repository is automatically left
   out.
4. **Knowledge surfaces.** These are other repositories, such as a marketing
   site, where Track may open draft PRs. Skip this unless you have one ready.
5. **Review and publish.** Check the summary and select **Publish site**.

Thally creates the repository from its starter template and runs the first
deployment. Mine went from **Building** to **Live** in about a minute, and Home
showed an agent readiness score of 89/100 for the starter content.

## 2. Clone the repository and learn its layout

The site summary on Home links to the repository. Clone it and install
dependencies:

```bash
git clone https://github.com/YOUR_ACCOUNT/YOUR_REPO.git
cd YOUR_REPO
npm ci
```

The repository has about 400 files, but you'll only touch a handful:

| Path | What it's for |
| --- | --- |
| `src/content/**/*.mdx` | Your pages. Each needs `title` and `description` frontmatter. |
| `docs.json` | Tabs, sidebar groups, and page order |
| `src/data/site.ts` | Site name, description, and header links (Cloud fills these in for you) |
| `AGENTS.md` | Instructions for coding agents, with a "Product context" section for you to fill in |
| `README.md` | Yours to rewrite |

Everything else is the Thally runtime. `starter-release.json` lists which paths
are framework-owned and which are yours: `README.md` and `AGENTS.md` are marked
`userOwnedNeverOverwrite`. Read `AGENTS.md` before editing. It sets the writing
standards and says which files to leave alone.

## 3. Replace the starter content

The starter ships with example pages that teach Thally itself. Delete the ones
you don't need with `git rm`, then make `docs.json` list only the pages that
exist. This is the navigation for this site, including the tab you're reading
now:

```json title="docs.json"
"tabs": [
  {
    "tab": "Docs",
    "groups": [
      { "group": "Get started", "pages": ["introduction", "quickstart"] },
      { "group": "Guides", "pages": ["guides/reduce-motion-toggle"] },
      { "group": "Reference", "pages": ["reference/motion-helpers"] }
    ]
  },
  {
    "tab": "Build with Thally",
    "groups": [{ "group": "Article", "pages": ["build-with-thally"] }]
  },
  { "tab": "Changelog", "href": "/changelog" }
]
```

If your product has no HTTP API, remove the **API Reference** tab *and*
`openapi.yaml`. When there's no spec, `/openapi.yaml` falls back to describing
the site's own read-only API, so agent discovery files don't break.

To write pages, I used a small set of components that the starter already
provides:

- `<Hero>` on the introduction page, which has `mode: home` in its frontmatter
- `<Steps>` and `<Step title="…">` for the quickstart and guide
- `<CardGroup cols="3">` and `<Card icon="…" href="…">` to link onward. Icons
  must come from an allowlist in `src/components/mdx/content-icon.tsx`.
- `<Note type="info|tip|warning|danger">` for callouts
- Fenced code blocks with a filename: `` ```tsx title="lib/motion.ts" ``

Use `###` headings for troubleshooting entries. Each one gets a stable anchor,
such as [`#cards-stay-invisible-after-turning-on-reduce-motion`](/guides/reduce-motion-toggle#cards-stay-invisible-after-turning-on-reduce-motion),
that other pages can link to.

## 4. Test every code sample before you publish it

This step matters more than any Thally setting. I created a throwaway app with
the exact command from my quickstart, `npx create-next-app@latest motion-demo --yes`,
pasted in each sample, and ran it in a browser. That caught three things I'd
have shipped otherwise:

- My first version of the toggle set React state inside `useEffect`. The
  current `eslint-config-next` rejects that with `react-hooks/set-state-in-effect`,
  so I rewrote it with `useSyncExternalStore`.
- An inline `<script>` in `layout.tsx` logs "Encountered a script tag while
  rendering React component" after Fast Refresh, but not on a full page load.
  I documented that rather than leaving readers to wonder.
- I reproduced the classic GSAP-in-React bug (`useEffect` plus `gsap.from()`
  under Strict Mode left an element stuck at `opacity: 0.0232`) and quoted the
  real numbers in the [troubleshooting section](/guides/reduce-motion-toggle#troubleshooting).

Record the versions you tested in the docs, so readers know what "works" means.

## 5. Check and build

Run Thally's content check and a production build before every push:

```bash
npx --yes @thallylabs/cli@latest check
npm run build
```

**Windows obstacle.** On Windows with Node.js in `C:\Program Files`, `check`
failed with:

```text
'C:\Program' is not recognized as an internal or external command,
operable program or batch file.
```

The CLI (`@thallylabs/cli` 0.8.124) runs its helper with
`spawn(process.execPath, args, { shell: true })` on Windows, and the unquoted
path breaks at the space. `check` only delegates to the `create-thally-docs`
package, so calling that directly works:

```bash
npx --yes create-thally-docs@latest check . --ci
```

It reported `0 error(s), 0 warning(s)`. The bug is tracked in
[thallylabs/thally#333](https://github.com/thallylabs/thally/issues/333), and I
opened a fix in [thallylabs/thally#342](https://github.com/thallylabs/thally/pull/342).

The production build took about a minute and a half and printed one framework
warning (the `middleware` file convention is deprecated), which isn't caused by
content.

Then run `npm run dev` and open `http://localhost:3040` to read the pages as a
reader would. I checked the navigation, every code block's filename label, the
heading anchors that other pages link to, and the external links.

## 6. Publish and verify

Commit only your content changes and push to the production branch (`main` for
a Cloud-created repository):

```bash
git add docs.json src/content AGENTS.md README.md
git commit -m "Add docs"
git push origin main
```

Thally Cloud picks up the push, shows the commit message under **Recent
activity** as **Building**, and switches to **Successful** when it's live. Mine
took about two minutes. Then confirm from outside the dashboard:

```bash
curl -I https://YOUR-SITE.thally.app/quickstart
curl https://YOUR-SITE.thally.app/llms.txt
```

The site also serves Markdown mirrors (append `.md` to a page URL),
`llms.txt`, `AGENTS.md`, `skill.md`, and a read-only MCP endpoint at `/api/mcp`.
You get all of these from the same MDX without extra work. After my content
went live, agent readiness rose from 89 to 97 out of 100.

## Obstacles and how I resolved them

| Obstacle | Resolution |
| --- | --- |
| **Continue with Google** failed with "Error 401: deleted_client" | Signed up and signed in with email instead |
| New repository defaulted to private, but reviewers needed to read it | Turned off **Private repository** in the Docs source step |
| `thally check` failed on Windows with `'C:\Program' is not recognized…` | Ran `npx --yes create-thally-docs@latest check . --ci` instead, then opened a fix ([#342](https://github.com/thallylabs/thally/pull/342)) |
| Starter's sample API reference didn't fit a docs site with no API | Removed the API tab from `docs.json` and deleted `openapi.yaml` |
| Starter README described Thally's template, not my project | Rewrote it; `starter-release.json` marks it as user-owned |
| Track only reacts to merged PRs; my product repository had none | Connected it anyway and noted that Track stays quiet until PRs are merged |
| Sample code failed the project's own lint rules | Tested every sample in a fresh app and fixed it before publishing |

## Next steps

- Add a custom domain from the site's domain settings. Thally shows the DNS
  records to add at your DNS provider.
- Fill in the "Product context" section of `AGENTS.md` so that Track and
  coding agents use your terminology.
- Connect an editor to the local authoring MCP server (`npx -y @thallylabs/mcp`)
  and the live site's read-only MCP endpoint (`https://YOUR-SITE.thally.app/api/mcp`).
